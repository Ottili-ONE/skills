# REPO_SHAPE — canonical repository shape (source of truth for the canonical-skills job)

Generated by SKL-W0-01 TASK-0004. Verified against the live tree on 2026-10-16.

## One tree, no duplicates

- Every skill lives under **exactly one** directory: `skills/<package>/<skill-name>/`.
- There is **no** top-level `business-de/` and no other duplicate of any skill tree.
- Proof: `find . -name SKILL.md | xargs -n1 dirname | xargs -n1 basename | sort | uniq -d`
  is empty (no two SKILL.md in directories of the same name).

## Flat directory per skill

Each skill is a single self-contained directory containing, as applicable:

```
skills/<package>/<skill-name>/
├── SKILL.md                # required — YAML frontmatter + body
├── references/             # DESIGN.md, procedures.md, SOURCES.md, EVALS.md, …
├── scripts/                # implementation scripts
├── tests/                  # *_test.py / test_*.py
└── config/                 # skill-specific config (e.g. versions.json, state files)
```

## Tests outside skill folders

- Repository-level tests live under `tests/` (root conftest + collection tests).
- Per-skill tests live under `skills/<package>/<skill-name>/tests/`.
- No test file is collected twice: `tests/conftest.py` excludes any stale duplicate
  tree from pytest recursion (guard, currently a no-op because no duplicate exists).

## Catalogue generated from folders

- `catalog.json` (root) is **generated**, never hand-edited: `scripts/gen-catalog.mjs`
  walks `skills/<package>/<skill-name>/SKILL.md`, parses the YAML frontmatter and
  writes one entry per skill with `name`, `package`, `description` and `paths`.
- Packages are derived from the `skills/` folders at generation time.
- `index/INDEX.md` and `index/skills.json` are generated by `scripts/build-index.py`
  from the same tree.
- CI runs `node scripts/gen-catalog.mjs --check` so the committed file cannot drift.

## Status / handoff docs

- No `STATUS.md` / `HANDOFF*.md` / `GAPS*.md` / `R3_PLAN.md` / `REVERIFY*.md` /
  `EVALS.md` / `*.log` / `state.json` at the repository root or under `docs/`.
- Proof: `git ls-files | grep -c STATUS` counts only per-skill files owned by other
  jobs (`skills/agentic-data/**`, `skills/business-de/**`); `git ls-files | grep
  -E 'STATUS|HANDOFF' docs/` is empty.
- The 9 remaining `STATUS.md` files live inside `skills/agentic-data/` and
  `skills/business-de/` and are owned by the `skills-agentic-data-r3` and
  `skills-business-de-r3` jobs — they stay.
