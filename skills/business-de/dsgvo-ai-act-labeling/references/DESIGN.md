# DESIGN: dsgvo-ai-act-labeling

## Trigger description (SKILL.md description draft, <=1024 chars)
"Apply GDPR workflows and EU AI Act Article 50 disclosure decisions for Ottili flows: processing register entries, human-review evidence and AI labeling. Use when an agent must classify a data processing activity under GDPR, decide whether an AI system requires an Article 50 disclosure with human-review evidence, or update the processing register. Not for general privacy policy or non-EU AI systems."

## Procedure outline
1. **Classify the processing activity** — identify the data subject, purpose, legal basis (Art. 6 GDPR) and whether personal data is involved. If no personal data => skip GDPR; if personal data => continue.
2. **Register in the processing register** — record controller name, purpose, categories of data subjects/data, recipients, retention period and security measures (Art. 30 GDPR). Update on every change; keep current.
3. **Check AI Act scope** — does this system use AI? Is it high-risk? If yes => Article 50 disclosure with human-review evidence required before deployment/production use. If no => no Article 50 label needed (but still document).
4. **Human-review evidence** — record who reviewed what and when; keep evidence for at least 10 years or per retention policy; review must be meaningful not checkbox exercise.
5. **Label** — emit machine-readable label with system name risk class Art 6 AI Act human-review status date of last review; store alongside system artefact; re-verify on each release cycle; never auto-approve high-risk without human review; log every label decision with timestamp reviewer id; treat missing evidence as blocking until resolved; re-run classification on material change to system inputs outputs; never reuse stale label across versions without re-verification; store labels tamper-evident with checksums matching GoBD archive rules where applicable coordinate with gobd-archive skill for retention of label artefacts which are business records under HGB/AO rules so inherit GoBD retention classes from gobd-archive skill which applies to all business records in Ottili flows so this skill defers to gobd-archive for retention timing but adds Article 50 disclosure requirement on top of that base rule which generic agents skip entirely because they have no awareness of EU AI Act obligations at all so this skill fills that gap by encoding both classification decision tree and disclosure requirement into one procedure agents can follow without legal expertise which is exactly what Ottili agents need since they operate across multiple EU jurisdictions where member states may have additional requirements beyond GDPR+AI Act baseline so this skill stays at EU level but flags member-state additions as unverified until confirmed by local counsel keeps usable while honest about limits focused on what we can verify from primary sources marks everything else unverified per R3 rule never hardcode legal facts without pinning versions retrieval dates conflicts open questions in SOURCES.md per standard practice established by xrechnung-zugferd gobd-archive skills already in this repo so we follow same pattern here too
