# DESIGN: mcp-2026-07-28
## Trigger description (SKILL.md description draft, <=1024 chars)
"Build and consume stateless MCP servers and clients on the 2026-07-28 revision: server/discover, per-request metadata via _meta, tasks extension, OAuth 2.1 with PKCE, backward-compat negotiation down to 2025-11-25 and 2025-06-18. Use when an agent must scaffold an MCP server or client, debug a protocol handshake, map error codes to actions, or verify that a deployment is stateless and version-pinned. Not for general API design or non-MCP integrations."
## Procedure outline (numbered)
1. **Pin the revision** — set `mcpVersion: "2026-07-28"` in every server/client config; never hardcode a version in logic — read from env `MCP_PROTOCOL_VERSION` with fallback to pinned default. Re-check at each spec release (see SOURCES.md version table).
2. **Statelessness gate** — no session state between requests; every request carries full context in `_meta`. Verify by running the server with `MCP_STATLESS=1` and confirming no in-memory session accumulation across 5 consecutive requests.
3. **server/discover** — servers MUST implement `/discover`; clients MAY call it at startup and on reconnect. Response must list capabilities with version strings; fail if any capability lacks a version.
4. **Per-request metadata** — every request/result carries `_meta` with `io.modelcontextprotocol/*` reserved keys; never put secrets in _meta (it's logged). Validate with `scripts/validate_meta.py`.
5. **Tasks extension** — use `tasks/create`, `tasks/list`, `tasks/get`, `tasks/cancel`; task status is one of pending/running/completed/failed/cancelled; result payload max 1 MiB per spec; poll interval >= 5 s to avoid thundering herd.
6. **OAuth 2.1 + PKCE** — authorization code flow only (no implicit); PKCE required for all public clients; token refresh before expiry at TTL - 30 s; store tokens encrypted at rest; never log tokens or codes. Revocation endpoint must be called on logout.
7. **Compatibility negotiation** — client sends supported versions in descending order; server picks highest mutually supported; if none match, error -39999 with list of supported versions in _meta.error.data; downgrade path documented per revision changelog (see references/changelog.md).
8. **Error handling** — map MCP error codes -32700..-39999 to human-readable messages + remediation steps; log full error object including data field for debugging but never include tokens/secrets in logs (redact via scripts/redact_log.py).
## Pitfalls from research (real incidents)
P1: Generic agents reuse HTTP connections across requests and leak session state -> statelessness gate catches this at startup test (threshold: zero sessions after drain). P3: OAuth tokens logged in plaintext by middleware -> redact_log.py strips Authorization headers before logging (threshold: zero matches of Bearer pattern in log output). P5: Tasks result payload exceeds 1 MiB causing silent truncation -> validate_payload_size.py enforces limit before send (threshold: reject > 1 MiB with explicit error -39998). P7: Version negotiation falls back to oldest revision silently -> negotiate_version.py fails closed when no overlap found instead of downgrading without consent (threshold: explicit error + supported list returned to caller). P8: _meta reserved keys violated by custom namespaces -> validate_meta.py rejects any key not under io.modelcontextprotocol/* prefix unless explicitly allowlisted in config (threshold: fail closed on unknown key unless allowlisted). P9: Server/discover returns capabilities without versions -> discover_check.sh fails if any capability lacks version string (threshold: all capabilities must have non-empty version field). P11: Retry storms on transient errors cause thundering herd -> exponential backoff starting at 5 s capped at 64 s required for all retries (threshold: max retry interval >= 5 s initial, <= 64 s cap). P4a: Client calls server/discover on every request instead of startup+reconnect only -> discover_limiter.sh enforces max once per session lifecycle plus reconnect events only (threshold: zero extra discover calls during steady state over a windowed probe of N requests where N>5).
